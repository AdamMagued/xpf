## Red before

On the parent `3a77951d144b7046389b5bdf2b3cfbdab708070c`, `cargo test
--locked --offline --bin xpf-userspace-dp tests_policy_revocation_8356::` ran
125 tests: 78 passed and 47 failed. The failing set is exactly the 47 tests
listed in #12262.

The principal fixture defect was that packets injected on tagged WAN
`reth0.80` (ifindex 12, parent 11, VID 80) carried VID 0. Since #11297
(`7d43c8346`), `unknown_ingress_vlan` rejects VID 0 on that tagged-only
child, so the common ingress guard recycled those frames before session
lookup and policy/NAT evaluation. Stamping VID 80 alone (the first pass,
`c8920f162`) fixed 44 of the 47; three issue-listed residual cells stayed red.

## Change

Added the configured VID 80 to the shared v4/v6 WAN metadata constructors
(`txn_wan_meta_v4`, `txn_wan_meta_v6`) and used them on the affected
reverse-session, DNAT, NPTv6, NAT64 and ICMP packet paths. Also corrected the
three residual fixtures:

- `an_unzoned_egress_is_re_judged_rather_than_skipped_9513` now uses the
  explicit interface-only next-hop syntax `@st0.0` (#12036); the former bare
  name did not resolve as a route, so the cell exercised #9513's legitimate
  NoRoute decline instead of the unzoned-egress deny.
- `refresh_skips_hainactive_preserving_recorded_10507` now uses
  `forwarding_without_fabric_dmz_10507()`, a no-fabric snapshot with the DMZ
  route and reachable neighbors, for both the inactive-RG refresh and the
  retention poll. The refresh therefore reaches `HAInactive`; the previous
  refresh snapshot produced NoRoute and reset the session to `Unvalidated`.
  The helper's `NeighborSnapshot` literals keep the `..Default::default()`
  tails #12272 gave the inline copy it replaces. The #7689 additive-literal
  ratchet (`protocol/cos_literal_guard_7689.rs`) requires exactly 26
  exhaustive `NeighborSnapshot` literals; without the tails this tree counts
  28 and the guard fails.
- `reverse_re_derivation_records_no_hit_9604` now has a connected LAN return
  path and neighbor for `10.0.61.102`, with WAN/LAN assigned to active RGs in
  the transaction fixture. It asserts the reply forwards (`tx = 1`) while
  policy counters remain unchanged. Without the return path the
  implicit-default counter moved from 0 to 1.

No production code changed.

## Residual-cell attribution

The three residual cells went red with #11315 (PR #11550, merged as
`4f706094c` before #11297), not with #11373 (`f3fe1dfc8`). They are
independent of the VLAN cause. Each failed with the same assertion as on
master:

- #9513: `out.revoked` 0, expected 1.
- #10507: revalidation kind `Unvalidated`, expected `RecordedEgress`.
- #9604: implicit-default hit counter 1, expected 0.

Evidence, from `tests_policy_revocation_8356::` runs. Where #11297 is an
ancestor, the VLAN-only first-pass fixture diff from `c8920f162` was applied.

- #11373's parent `dfd14ee82` and `f3fe1dfc8` itself: 96 passed, 3 failed,
  with the same three cells failing.
- A first-parent bisect from `b7450692f` (98 passed) to `dfd14ee82`: the
  first bad master commit is the #11550 merge `4f706094c`. The previous
  master commit, `6801f76eb`, passed 98.
- Inside #11315, on top of `b7450692f`: `f1cf59763` ("reject stale neighbor
  MACs in cached sessions") failed only #9604. `c18900abb` ("reject cached MAC
  while neighbor is absent") failed all three.

`c18900abb`'s risk note says that while a neighbor is absent, an existing
session re-resolves instead of serving its cached MAC. From then on these
cells depended on route state that their snapshots lacked: a resolvable
`st0.0` next hop, a DMZ route, and a LAN return route.
