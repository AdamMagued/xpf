# Issue #12210 — Stamp successful config-apply retries

## Why

A successful config-debt retry could converge the dataplane without recording the active digest. `ActiveApplied()` then reported false after convergence, so a newly constructed session-sync object skipped active zone-ownership seeding and withheld the BulkAck. Successful commit-confirmed rollback applies already stamp through the #12073 policy-invalidation debt discharge (`dischargePolicyInvalidationDebtLocked` -> `MarkAppliedDigest(debt.appliedDigest)`); that is not a defect owned by this change.

## What

The retry owner captures `ActiveDigest` while holding `applySem` and stamps that captured digest only after a successful retry with no outstanding policy-invalidation debt. The retry lifecycle regression reconstructs and publishes a fresh session-sync object, verifies its trust-zone ownership snapshot, and observes a matching BulkAck over a live loopback session-sync pair. A real-apply rollback control documents that #12073 already stamps that path on the base.

## Validation

 - **RED before:** On base `83b5c955335f16d8c7835f206b210ce3ae1a5fe5`, `go test ./pkg/daemon -run '^TestBootRetryReconstructsZoneSnapshotAndReceivesBulkAck12210$' -count=1` failed on the missing retry marker, zone snapshot, and matching BulkAck. The rollback control passes on this base: #12073 stamps through `dischargePolicyInvalidationDebtLocked` -> `MarkAppliedDigest(debt.appliedDigest)`.

 - The base was already successful on rollback; the new deferred-publish and outstanding-debt cells cover the fail-closed guards, and the #6296 retry cell pins captured-digest behavior.
 - **GREEN after:** The targeted retry, rollback, zone-seed, #6296 marker, and BulkAck tests passed; `go test ./pkg/daemon -count=1` passed; `go build ./...` passed; `gofmt -l` on all changed Go files returned no files.
 - The reconstruction test uses loopback sockets only; no live cluster was changed.

## Risk

The retry marker is keyed to a digest captured while `applySem` is held and is written only after successful apply and policy invalidation, avoiding certification of an unapplied concurrent promotion. The existing rollback discharge continues to stamp only after its invalidation debt is cleared.
