# #12188 — inspect image keyrings before publish

## Why

At current base `02a768c34fc87b3b8bdb740bad2b72f83b2b07ac` (the `origin/master`
tip used for this fold), `publish.py gate_provenance` accepted a signed,
provenance-valid qcow whose guest carried `.placeholder` (direct base-code
reproduction exited 0). The image-only path bypassed the apt package gate.
The prior bake-provenance test mock returned inventory text for the keyring
`virt-cat` call, so its 23-test run errored before exercising the gate. The
default package fatal and unconditional unsigned-bake refusal also blocked
dev/dogfood workflows.

## What

`debian/rules` now warns and installs the placeholder for default dev builds;
`XPF_RELEASE=1` fails without the real key, while the explicit
`XPF_ALLOW_PLACEHOLDER_KEYRING=1` remains a dev-only package override. Publish
still rejects placeholder packages and images. Bake reads and validates the
guest keyring only when signing; refusal text says it will not sign the image.
Unsigned dev artifacts can be produced but remain unpublishable. Publish
independently inspects every qcow keyring, rejects unreadable, invalid, or
placeholder content, and checks that a present installer's embedded key is
covered. Binary guest decode failures use controlled `die()` errors; redundant
empty-fingerprint branches were removed. Regression tests cover missing-key
package and image paths, real publish fixtures, and retained-v1 K1-only images
blocking a v2 K1+K2 installer. Distribution docs describe pruning retained v1
artifacts or rebaking them with both keys before publishing the rotation. The
distribution selftest reports missing tools and its full skip count, fixes the
umask and reports dpkg build failures; runner docs no longer claim fast or
hermetic execution.

## Risk / residual

Default dev packaging deliberately installs a marked placeholder and is not
releasable or publishable. Release packaging requires the real archive key and
`XPF_RELEASE=1`; signed bakes require the key, while unsigned dev bakes remain
unpublishable. Validation used synthetic qcow files and throwaway signing
fixtures; no full production-base image bake or live-cluster validation was
run.
