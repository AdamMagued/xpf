# #12270 — resolve included test fixtures in the source scan

- **Base**: `feb35c419a709a78437754ee7b54b7b01a9b9b18` (PR parent)
- **Branch**: `fix/12270-campaign-pub`

## Why

The fixture-classification agreement guard treated `afxdp/icmp_ptb_primary_fallback_11437_tests.rs` as production. The file is brought into `icmp_ptb_tests.rs` with `include!`, and that containing module is declared under `#[cfg(test)]`; the scanner followed module declarations but not included source files.

## What

`cfg_test_modules` now records code-only, line-start `include!` calls with
ordinary quoted paths, resolves them relative to the containing source file,
and adds their targets to the existing source-edge closure. Comments and
strings are blanked before matching, and the macro name boundary is checked.

`include!` copies text, so one file can be included by a test-only file and
also declared or included by production. An include target is therefore
admitted only once every ungated `mod` or `include!` edge into it starts from a
test-only file. Test-gated declarations and includes are seeds, not edges, so a
gated include never counts against its own target.

The shared `blank_comments_and_strings` helper, which the #6929, #7015, #7053,
#8121 and #7689 guards also call, changed in two ways:

- It ends a `/* */` block only at the matching close, because rustc nests
  block comments.
- It blanks whole char and byte-char literals (`'"'`, `b'"'`, `'\''`). It tells
  them apart from lifetimes and labels the way rustc's lexer does. Before
  this, the quote in `'"'` opened a phantom string, so code read as string
  and string read as code up to the next quote.

## Risk

Only standalone, line-start `include!("path")` forms (optionally
`::include!`) with ordinary quoted paths are followed. `concat!`, `env!`,
raw-string paths, and multiline or whitespace-separated forms remain
unresolved. This test-only classifier determines which production files the
#6929, #7015, #7053, and #8121 canaries scan. A false edge can silently
reclassify a production file and its module subtree as fixtures; #8325 only
floors `only_derived` and does not print those names, so that direction is not
caught by its census.

The include admission check sees only the declarations this scanner resolves.
The scanner resolves a crate root's `mod x;` as if `main.rs` were an ordinary
file, to `main/x.rs`. So a top-level module declared only from `main.rs` does
not keep a test `include!` of it in production.
`cfg_test_include_targets_shared_with_production_stay_production_12270` pins
that limit. No such include exists today; the only include target is the ICMP
fixture. Resolving crate roots properly would also reclassify five top-level
`#[cfg(test)]` modules (`drop_order_probe.rs`, `fairness.rs`, `test_alloc.rs`,
`test_ports.rs`, `test_zone_ids.rs`), so it is left to a separate change.

Five guards share the blanker. On this tree, none of their measured inputs
changed (see Validation). No production runtime behavior or live cluster was
exercised.
