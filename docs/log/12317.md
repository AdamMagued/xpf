# Issue #12317 — preserve exclusions across physical/unit overrides

- **Issue:** A physical `netconf-ssh` override unioned with a same-unit `all; ssh except` re-admitted TCP/22 through the alias.
- **Base:** `a11e59eac398970413aac11b6bd27318bead06c8`.
- **Branch:** `fix/12317-campaign-pub`.
- **Worktree:** `/var/worktrees/campaign-pub/wt-12317`.
- **Issue body:** Read before implementation; #12317 identifies `MergeHostInboundTraffic` as the provenance-losing union.

## Change

`MergeHostInboundTraffic` now unions the compiler-retained service/protocol exclusions along with the positive tokens, then reapplies the combined exclusions. A positive alias from either interface scope can no longer restore a tuple excluded by the other. The local duplicate-host-address gate mirror and the hand-built `ZoneConfig` fallback use the same rule; compiled resolver stamps already flow through the shared merge. Zone/interface replacement remains unchanged (#6515).

The regressions assert exact TCP ports on both address families: the cross-scope cases must deny TCP/22, retain TCP/830 through the independent `netconf` service, and preserve unrelated HTTP/80. Coverage includes strict and lenient physical-alias/unit-exclusion and reversed-scope combinations, zone/interface replacement controls, a hand-built legacy resolver control, and same-stanza controls.

## Risk and residual

Exclusion remains token-granular: an alias whose match overlaps an excluded tuple is removed as a token, while separately named non-overlapping services remain (for example, `netconf` retains TCP/830 after `ssh except`). Cross-scope `any-service` diagnostics (#12313) and name-only `protocols` exclusion semantics (#12318) are unchanged. No live cluster or network configuration was mutated.

### Folded

- **Protocol and enforcement coverage.** `TestHostInboundCrossScopeProtocolExcept12317` pins a literal `protocols all` against `all; ospf except` in both scope orders, strict and lenient, on the resolver and on the duplicate-address gate. `TestHostInboundCrossScopeExceptReachesEnforcement12317` (`pkg/dataplane/userspace`) compiles both alias orientations plus a protocol exclusion and checks what the planes consume: the kernel-nft views that scope the unit's IPv4 and IPv6 addresses, and the AF_XDP unit row. TCP/22 and IPv4 OSPF are denied there; TCP/830, TCP/80 and BGP stay admitted.
- **Explicit-token narrowing.** An exclusion in either scope also removes what the other scope names explicitly. `TestHostInboundCrossScopeExceptRemovesExplicitTokens12317` pins `all; ssh except` + `ssh` and `all; ospf except` + `ospf` in both orders. The new commit-time advisory `validateHostInboundCrossScopeExceptWarnings` replays the resolver walk with a provenance-free union (`resolveInterfaceHostInbound` takes the merge as a parameter). It warns once per narrowed unit, naming every contributing stanza and each token the union no longer fully admits. It skips lifelines and `any-service` unions, and returns before either walk when no interface stanza carries an exclusion. `docs/host-inbound-service-matrix.md` now states the rule, the corrected precedence formula and the upgrade narrowing; `debian/changelog` carries the upgrade note.
- **Merge cost.** `MergeHostInboundTraffic` filters each input only by the other input's exclusions. Every stanza is already filtered by its own, so a single input is a plain copy, and a physical override that fans down to many units is not re-filtered once per unit. The duplicate-address gate calls the shared merge (`mergeHostInboundOverrideLocal` is deleted). The union stays exactly deduplicated when a literal `all` expands.
- **Nits.** The merge doc comment no longer overclaims its dedup. The retained exclusions are no longer described as compiler-only (`types_security.go`, `compiler_security_zones.go`).
