# Issue #12184 — validate the qualified-next-hop metric

## Why

The qualified-next-hop `metric` leaf was untyped, unlike its sibling `preference`. Strict schema validation therefore let `-1`, `4294967296`, and non-numeric values such as `abc` reach compiler paths that ignore unparsable integers or treat out-of-u32 values as tier 0. That silently erased the authored failover order and omitted invalid FRR metric exports.

## What

- Typed the metric leaf as an integer in `0..4294967295`, matching the userspace tier and FRR export consumers. Zero is the primary metric tier and is explicitly valid; the u32 ceiling is the consumer boundary. This intentionally differs from preference's `1..254` range.
- Made strict schema walking use the existing #9235 QNH flat-run expansion for
  `qualified-next-hop` children, matching the compiler view for both typed
  metric and preference leaves. Invalid preference `0`, `255`, and `abc` now
  reject in flat interface/metric chains (valid range `1..254`); tolerant
  `Store.Load` behavior is unchanged.
- The expansion newly admits 18 QNH spellings refused by the prior strict
  gate. With G = next-hop, X = interface, N = preference, and M = metric:
  - Flat: `G preference N metric M`; `G preference N interface X`.
  - Braced fused-child: `{ interface X metric M; }`,
    `{ preference N metric M; }`, `{ metric M interface X; }`,
    `{ interface X preference N metric M; }`,
    `{ interface X preference N; }`, `{ preference N interface X; }`.
  - Packed on the QNH line: `interface X preference N metric M`,
    `interface X metric M`, `preference N metric M`, `metric M interface X`,
    `interface X preference N`, `preference N interface X`.
  - Route-packed: `route R qualified-next-hop G interface X metric M`,
    `route R qualified-next-hop G preference N metric M`, and
    `route R qualified-next-hop G interface X preference N`.
  - Also accepted: `interface preference metric M`, where `preference` is
    the literal interface name.
- Three placements are separately pinned variants, not new spelling classes:
  routing-instance braced `interface X metric M`, routing-instance packed
  `interface X preference N metric M`, and groups braced `interface X metric M`
  with `apply-groups`.
- The compiler consumes the authored values in these forms. Tests pin F05/F06
  metric-first chains plus braced fused-child and packed multi-modifier cases.

## Risk / residual

- The strict gate now accepts 18 QNH spellings refused before #12184; the
  `0..4294967295` metric boundary is unchanged. Expanding flat runs also makes
  strict commit reject preference `0`, `255`, and `abc` in flat interface and
  metric chains; valid preference is `1..254`. The parent accepted those
  chains, and preference 255 maps to FRR `DISTANCE_INFINITY`, so that backup
  never installs. `Store.Load` remains tolerant and reports schema warnings,
  but a later strict commit rejects these values.
- Repeated hierarchical qualified-next-hop blocks still compile into separate
  entries: the interface-only entry has no metric, so `StaticRouteNextHopTiers`
  puts the intended backup in the primary ECMP tier (preference 5, metric 0)
  instead of its intended metric-100 failover tier. This measured consequence
  is scope-deferred to #12308; no merge or duplicate rejection is added.
- No live cluster or hardware was mutated.
