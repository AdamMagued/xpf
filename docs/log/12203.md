# Issue #12203 — fail closed in chained-crash dual-active check

## Why

`check_no_dual_active` must not turn an unreadable status or a node with no scoped RG role into a positive HA assertion. The earlier grep counter treated a missing local-node row as “not primary”; it also matched RG10 as RG1.

## What

`deploy_node_rg_role <node> <rg>` reads the exact role field from exactly one matching node row inside the exact RG header, and fails closed for empty, malformed, unconfigured, missing, or duplicate rows. Both `test-chained-crash.sh` and `test-ha-crash.sh` source this shared reader and use byte-identical dual-active checks. Both status commands are read before reporting failures; a missing scoped role and a no-primary RG fail, and `no dual-active` passes only when every checked RG has exactly one primary. The RG header match is exact, so RG10 cannot contaminate RG1.
