# #12177 — refuse envelope-incompatible cuts without wedging rollback

- **Issue**: #12177 — refused envelope checks left cuts unrecoverable and could trust unconfirmed replacement bytes.
- **Branch**: `fix/12177-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12177`
- **Base**: `83b5c955335f16d8c7835f206b210ce3ae1a5fe5`

## Why

A staged downgrade refused before PREFLIGHT could leave an in-flight journal, blocking both reruns and explicit/default operator rollback. Separately, a same-tag replace could copy the committed predecessor's stamp onto different bytes that had never been health-confirmed; if the final envelope check then refused, those bytes could remain eligible as the default rollback target.

## What

- Check the staged reader at INIT; clear stale journals on INIT/resumed-PREFLIGHT refusals and clear the journal on a pre-STOP envelope refusal, before any live mutation.
- Preserve a committed predecessor stamp across replacement only when every managed binary hash matches the pinned source. Different bytes are marked non-committed before replacement; a preserved stamp is demoted after the pre-STOP check passes.
- Cover fresh/resumed refusals, default and explicit rollback after pre-STOP refusal, byte-identical/different-byte replacement, failed-target exclusion, and wrapped refusal classification.

## Risk / residual

The regression uses the package's fake system and temporary directories; no live cluster or systemd unit was exercised. A byte-identical predecessor remains eligible through a pre-STOP refusal; a replacement with changed bytes is excluded, and a cut that passes the gate marks the reused target in-flight before STOP. Refusal errors direct operators to re-stage an envelope-compatible target or run `xpfd upgrade --rollback` with `--target <compatible-version>` when default selection is unsuitable, after the refusal journal is clear.
