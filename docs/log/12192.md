# Issue #12192 — skip dead workers during session-upsert fan-out

## Why

Session replication attempted an `UpsertSynced` command for every sibling queue, including queues whose worker supervisor had already marked dead. A full abandoned queue therefore followed the generic bounded-push drop path instead of being skipped and counted as a dead-worker shed.

## What

Each reconcile generation now pairs each worker command queue Arc with the same runtime atomics used by its worker supervisor. Session-upsert fan-out checks that liveness before acquiring the queue, skips dead workers, and increments the shed metric; live siblings still receive the replica. The enqueue metric counts only live queue attempts, so `enqueued / upserts` is the live-sibling multiplier and excludes shed dead-worker legs. Queue identity, rather than a reusable worker ID, selects the liveness slot. Replica conversion is lazy so an all-dead fan-out does not clone a session entry.

## Risk / residual

The load-bearing production wiring is pinned by a drop-in test that launches real healthy stubs and a real supervised panic; see Validation. Session-delete replication and local-tunnel `UpsertLocal` fan-out still lack dead-worker checks, as do CoS redirect and PPTP broadcast producers; their queues remain bounded by `push_bounded`. Unassociated queues retain existing bounded-push behavior. No live cluster or hardware was mutated.
