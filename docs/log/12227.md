## Change

- The shared policymatch usage text now says omitted source/destination IP matches any address, while omitted protocol, port, or ICMP type/code never matches a constrained term; unconstrained terms may still match. A partly specified query's verdict is not exhaustive: a skipped deny can let a later permit match.
- Local and remote CLI usage-output tests pin that user-visible explanation. The matcher regression pairs the omitted-protocol default-deny result with its permitted `tcp`/80 completion.
- The Junos CLI reference, matcher comments, and proto source-port documentation now describe the same contract. Matching behavior is unchanged.
