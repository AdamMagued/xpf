# Issue #12238 — reject contradictory weekday scheduler statements

## Why

`compileSchedulers` merges every statement for a weekday into one
`SchedulerDayWindow`: `start-time`/`stop-time` keep the last value, while
`all-day` and `exclude` are ORed (`compiler_system.go`). Runtime checks
`Exclude`, then `AllDay`, before the time bounds. A `monday all-day`
statement next to a separate `monday { start-time 09:00:00; stop-time
17:00:00; }` statement therefore enforces the policy all day, and a separate
`exclude` statement can never be superseded. The issue accepts either
supersede semantics or a strict rejection naming the scheduler; this change
rejects.

## What

`validateSchedulerWindowPairs11358` (the #11358 validator, run on the node0
and node1 group expansions before node-local compilation) records each
weekday statement separately: one `monday …` node after flat-run expansion,
including flags carried in the node's keys. It diagnoses:

- an `all-day` or `exclude` statement that does not itself carry the complete
  start/stop pair that the day's statements supply; and
- `all-day` and `exclude` in different statements.

Each split has its own message naming the scheduler, the weekday, and
#12238. Strict compilation (commit check, commit) rejects. Tolerant
compilation (`Store.Load`, `SyncApply`) warns and keeps the union window.
Statements count separately in one block, in repeated blocks, and in repeated
roots. One statement keeps the #10006 behavior. A flag next to a partial
pair, distinct weekdays, and repeated `daily` statements (a last-wins scalar)
stay valid. The weekday merge in `compiler_system.go` is unchanged.

The outcome depends on the stored shape. Flat `set` lines that build one
`monday` node, `load merge` into an existing `monday { … }` container, and
group inheritance merged into an inline `monday { … }` each produce one
statement. Those shapes still compile all-day without a diagnostic and are
tracked by #12643; covering them means deciding the #10006/#11641
single-statement semantics.

The `pkg/scheduler` runtime test from the first revision was removed: it
passed on the base and pinned the widened all-day permit as expected
behavior.

## Risk / residual

Strict commit and commit check now refuse split weekday statements, including
in-block shapes that previously committed: `set … monday start-time …` after a
stored `monday all-day;` leaf, `load merge` of a window over that leaf, and
`load override` text with repeated statements. A stored config with split
statements still loads and syncs with a warning and keeps the all-day union,
but the next commit is rejected until the statements are combined or removed.
That includes unrelated edits and a commit after a rollback to such a
revision.

Shapes that compose into one statement still enforce all day without a
diagnostic (#12643). `{ monday { all-day; exclude; } }` plus
`{ monday all-day; }` is rejected even though its union equals the first
statement alone.
