# Issue #12255 — keep absent neighbors stale in session resolution

## Why

`afxdp::tests_bind_forward::session_resolution_falls_back_to_cached_neighbor_on_miss` failed on master with `MissingNeighbor` vs `ForwardCandidate`. The cell is older than #11315. It cleared every neighbor binding and still expected a session hit to reuse the cached `ForwardCandidate` MAC. #11315 (`c18900abb`) deliberately made a missing live binding stale in `cached_session_resolution` and in the flow-cache seed guard. That change gave live-neighbor fixtures to the tests that exercise cached reuse, but it missed this cell. The test was wrong; the dataplane was right.

Two production fallbacks were tried on this branch and withdrawn:

- **Epoch-0 fallback**: allow an absent binding while its neighbor shard epoch is zero. It bypassed the connected IPv4 directed-broadcast deny, served removed static MACs, and trusted peer-synced cached MACs (#12309).
- **Provenance gate**: allow the fallback only for local `ForwardFlow` hits with a current forwarding generation and epoch zero. It still served a removed snapshot-seeded MAC. The Go neighbor manager's authoritative replace (#1197, `Coordinator::apply_manager_neighbors`) removes the row from `forwarding.neighbors`. The shard epoch advances only for keys in the dynamic map, and the republish reuses the current validation, so neither gate saw the removal.

## What

- `userspace-dp/src/afxdp/session_glue/mod.rs` is unchanged from base, so an absent live binding stays stale (#11315).
- `tests_bind_forward.rs`: the cell is now `session_resolution_absent_neighbor_is_stale_live_binding_reuses_cache_12255`. With the binding absent it asserts `MissingNeighbor` and no MAC. It then seeds the matching live binding `(12, 172.16.80.200) -> 00:aa:bb:cc:dd:ee` and asserts the cached `ForwardCandidate` fast path: egress/TX ifindex, neighbor MAC, source MAC and VLAN.
- `session_glue/tests.rs`: added `session_hit_reresolves_after_manager_replace_removes_snapshot_neighbor_12255`. It installs a local `ForwardFlow` session for a snapshot-seeded neighbor and removes that neighbor with an empty authoritative manager replace. It asserts the preconditions: no dynamic row, binding gone, `(config_generation, fib_generation)` unchanged, shard epoch 0. It then asserts that the production `resolve_flow_session_decision` re-resolves to `MissingNeighbor` with no MAC.

## Validation

Run from `userspace-dp/` with `cargo test --locked --bin xpf-userspace-dp`.

- **RED before**: on base `83b5c9553` and on master `2399eb691` the original cell fails with `left: MissingNeighbor, right: ForwardCandidate`.
- **GREEN after**, on base plus this change:
  - each new cell passes on its own (`-- --exact`);
  - filter `12255`: 2 passed;
  - filter `11315`: 4 passed;
  - `afxdp::tests_bind_forward::`: 38 passed;
  - `afxdp::session_glue::tests::`: 218 passed, 1 ignored.
- **Mutation checks**: both withdrawn fallbacks were restored over the new tests.
  - With the epoch-0 `mod.rs` from `5a3574527`, both new cells fail with `ForwardCandidate` vs `MissingNeighbor`. The four `11315` cells still pass, so they do not detect that fallback.
  - With the provenance-gate `mod.rs` from `99e840371`, the production-path cell fails with `ForwardCandidate` vs `MissingNeighbor`. The helper-level cell passes, because that version's strict helper stayed strict. To compile, three test calls of `cached_session_resolution` were given the strict provenance argument.
- **Full binary suite**: the merged tree (`2399eb691` plus this change) had 114 failures against 115 on a fresh `2399eb691` run. The one difference is the old cell name, which is now renamed and passing; no new failures. On base plus this change, no test failed that had not already failed on base.
- No live cluster was exercised.

## Risk / residual

This is a test-only change. The production session and flow-cache neighbor paths are unchanged: while a binding is absent, established sessions re-resolve instead of reusing the cached MAC (#11315). The full suite on master still has unrelated pre-existing failures.
