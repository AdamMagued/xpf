# Issue #12239 — reject unknown scheduler weekdays and window leaves

## Why

The time-range scheduler schema accepted unknown children. `compileSchedulers`
only records the seven recognized weekday names, so a misspelled weekday such
as `modnay` was silently discarded. A scheduled deny with that as its only
window therefore had no window and never became active.

## What

The named `scheduler <name>` schema node now opts into closed-world
validation. Strict checks reject unknown scheduler children and weekdays,
plus a misspelled or second statement packed onto a hierarchical day line
(`daily all-dya;`, `monday all-day exclude;`; the compiler reads only the
first), with diagnostics naming the scheduler. Junos `description text` is
modeled (display-only), and #8939 flat-set day runs are expanded before
validation exactly as the compiler reader expands them. The
empty-scheduler control remains valid.

## Risk / residual

Strict `commit`, `commit-check`, and `check-config` now refuse configs they
used to accept: unknown scheduler children and weekdays (`modnay`, `Monday`),
unknown day-window leaves, a misspelled packed day tail, and a hierarchical
day line packing a second statement (`monday all-day exclude;`, which the
base compiled as all-day alone). A persisted config carrying one of these
still loads (Store.Load and SyncApply downgrade the schema error to a
warning), but the next commit fails until that line is fixed. A persisted
valid description or #8939 flat run no longer blocks an unrelated commit.
Direct `CompileConfig` callers bypass the strict gate.

Junos `description text` is accepted for closed-world completeness but is
display-only: the compiler has no `SchedulerConfig.Description` field.

Expanding day runs also makes the `daily` / weekday
`start-time X stop-time Y` one-liner commit-acceptable (flat and
hierarchical). The flat-set weekday form leaves a stray scheduler-level
`StopTime` through the unchanged #9235 residue hoist. Without a daily or
scheduler-level window, the other weekdays resolve to that half-window, fail
closed (inactive, as with no window), and log
`scheduler: incomplete time window, failing closed` on each evaluation. With
a daily or scheduler-level `start-time` / `stop-time` window, strict commit
refuses the pair (#11358 `conflicting repeated time boundaries`) instead of
letting the stray replace that window; a `daily all-day` window keeps
precedence over it. `TestClosedWorldSchedulerWeekdayRunKeepsDailyWindow12239`
pins the no-replacement property. Stopping the hoist from descending into day
containers is not part of this change and has no issue yet.

Scheduler-level `start-time X stop-time Y` and `start-date X stop-date Y`
one-line runs remain strict-rejected.
`apply-groups-except` / `apply-macro` rejection is tracked by #12635;
weekday-on-scheduler-line parsing by #12636; scheduler one-line compatibility
by #12637. These follow-ups are not folded here. No live cluster was modified.
