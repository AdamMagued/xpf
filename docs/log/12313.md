# #12313 — diagnose cross-scope inert host-inbound `except`

- **Timestamp**: 2026-10-09
  - **Why**: Runtime unions a physical-interface host-inbound override with the override on each same-zone logical unit (#3720). The existing #12054 gate inspected each authored stanza separately, so a retained `any-service` in one contributor and a known `except` in the other left the effective unit admitting everything without a strict error or lenient warning.
  - **What**: Extend the independent full-admit/except gate to correlate the actual `ResolveInterfaceHostInbound` physical↔unit union with the two source stanzas. Strict compilation rejects known system-service or protocol exclusions made inert by the sibling `any-service`; tolerant compilation warns with both override scopes named and preserves the established runtime tokens. The issue text also cited zone `any-service` plus interface `except`; that is not a runtime union because #6515 makes the interface stanza replace the zone stanza. A regression pins that shape as silent and confirms its effective interface set excludes the zone full-admit.
