# #12527 — canonical-command check accepts option-suffixed table entries

- **Timestamp**: 2026-10-10 (PR #12560 review fold 2026-10-12)
- **Action**: Gate the `everyWordIsAKeyword` leaf early-return on position (`i == len(words)-1`) so trailing words after a leaf are rejected.
- **Base**: `origin/master` `3e65aedcf` (rebased from `f9cb48ed8` for the PR #12560 review fold)
- **Files**: `pkg/grpcapi/authz_command_table_7172_test.go`, `docs/log/12527.md`; review fold: `pkg/grpcapi/authz_command_table_topics_7172_test.go`, `pkg/grpcapi/authz_command_gate_7172_test.go`, `pkg/grpcapi/authz_command_table_topics.go` (comment only), `pkg/grpcapi/README.md`
- **Parent**: #12096 (Opus R3 R9 on PR #12343)

## Why

The helper returned `true` at the first leaf unconditionally, never
examining trailing words: `show security flow session summary zone`
passed (`summary` is a leaf, `zone` unchecked) while Canonicalize also
accepts it via Options re-entry (#9505, correct operator behavior). All
three validity arms went green on a non-pure path, and the same holds for
`summary brief` and `zone trust`. A sibling after a leaf outside an
Options node (`show version configuration`) passed the keyword arm too,
but Canonicalize already refused it (`CanonicalUnknown`, #8289).

## What

One predicate: leaf allowed only as the LAST word (`return i ==
len(words)-1`). Canonicalize untouched (Options re-entry is legitimate).
All current table entries audited green (bare Options nodes end non-leaf;
`summary`/`sort-by bytes`/zone-leaf rows end leaf-last). Topics/verb
tables share the helper → inherit the tightening.

## Review fold (PR #12560)

The Opus review of `c9c613a79` returned NEEDS-FOLD: the fix is correct and
only tightens, but comments and docs the tightening made false still
described the old behavior, and the failure message named the wrong cause.

- **F1** — the summary-deny fixture comment in
  `authz_command_gate_7172_test.go` said a mis-charge to `…summary zone`
  passes `TestEveryMappedCommandIsCanonical7172` and only the `$` anchor
  catches it. The table test now rejects it, so the comment calls the
  anchor one of two guards and records that it was the only one before
  this fix.
- **F2** — the `assertCanonicalCommands` comment said two arms are live,
  that Canonicalize catches `show version zzbogus`, and that no mutation
  reaches canon != cmd. Now the keyword arm catches every entry whose
  words are not a tree path; Canonicalize cannot fail on an entry the
  keyword arm passed (`resolveTreeWord` takes its exact-hit branch for
  every word, so both walk the same nodes); and whitespace reaches
  canon != cmd. The comment says so and keeps the pre-#12527 behavior as
  history.
- **F3** — both keyword-arm failure messages blamed a value slot, but
  `summary` and `zone` are both keywords. They now name both causes, and
  the helper's doc comment states the leaf-last rule.
- **F4** — the README validity rule, and the CANONICALITY bullet in
  `authz_command_table_topics.go` that states the same rule, gain the
  nothing-after-a-leaf clause.
- **N1** — this log and the commit message no longer say `show version
  configuration` passed all three arms, say test-time rather than
  build-time, and cite #12582 for the REST gap.
- **N2** — the mechanism pin used `…summary zone`, which the CLI refuses
  (`missing value for "zone"`). It now pins `show security flow session
  summary zone trust`, which the CLI runs, and the helper rows include it.
