## Keep dispatch tests on the production path

All ten #12268 cells construct `PendingForwardRequest` directly through the shared `test_live_forward_request_for_frame` fixture, bypassing the XDP shim that stamps `flow_src_addr` and `flow_dst_addr` from the packet. The fixture leaves both fields zeroed, which the final-TX #11074 source-martian backstop correctly reads as `0.0.0.0` (IPv4) or `::` (IPv6) and rejects before the tests reach their intended dispatch paths. That one root cause produced every failure the issue lists:

- six enqueue-failure cells: mirror accounting, enqueue-failure handling, oversized-frame recycling, direct-TX frame accounting, and PAT translation;
- three NAT64 cells: the #6922 ext-header-before-fragment attribution, the #8890 tunnel-first attribution, and the #8890 no-plaintext-onto-tunnel gate, whose untunnelled control never reached TX;
- the #9782 segmentation cell, which saw zero segments.

While these cells were red for that reason, the #8890 gate and the #6922 attribution order had no effective coverage.

Each affected fixture now copies its wire endpoints into metadata, following the existing `ptb.rs` and `nat64_fragment_11353.rs` pattern: IPv4 `frame[26..30]` / `frame[30..34]` in `enqueue_failure.rs` and `segmentation.rs`, IPv6 `frame[22..38]` / `frame[38..54]` in `nat64_attribution_6922.rs`. The `Prebuilt` fabric-redirect cell stays unstamped because prebuilt frames are exempt from the backstop. No production guard, assertion, or expected outcome changed.
