# 12191 — refresh stored AppID labels after policy revalidation

- **Timestamp**: 2026-10-08

## Why

Conntrack stores the AppID resolved when a session is created, while RT_FLOW create/close labels and application filters use the current application catalog. After an application redefinition without `PolicyRematch`, live TCP/443 sessions could therefore be shown/cleared as A while close events resolved B. The affected flow is the AppID-enabled stale-session path.

## What

- On a stale established-session PERMIT, restamp the canonical forward conntrack row only after the zone-policy verdict makes the session fresh. A reverse hit with an authoritative local forward companion restamps that same forward row; it does not target a reverse row.
- Update only the conntrack `app_id` field with a read/modify/write for IPv4 and IPv6 rows, preserving counters, timestamps, NAT state, and session ID.
- Test coverage includes the direct stale A-to-B permit, production
  descriptor IPv4 DNAT (wire :443 versus translated :8443), reverse-hit
  IPv6 and reverse-DNAT port resolution, same-AppID first hits that skip
  writes plus a later stale restock, and Fresh-forced no-restamp. RT_FLOW
  create/close and Go filtering tests are characterization coverage: they
  pass on master and pin their existing contract, not restamp wiring.
- Exclusions: host-bound `LocalDelivery`, type-dependent ICMP, reverse-only
  hits without an authoritative local forward companion, denied/declined
  paths, idle sessions until an eligible hit, and the `stored_pair_only`
  permit path do not restamp. Fresh-generation hits, including Fresh-forced
  revalidation, also do not restamp.

## Risk

The PR contains three `#12191` commits based on PR base
`1e5b4dfe6`.

Each eligible stale permit still performs one map lookup. The
same-AppID branch in `restamp_bpf_conntrack_app_id` runs through the
test syscall helpers: both first hits of a new pair skip the
`BPF_EXIST` update, while an 11→22 label change performs exactly one.
Removing the production same-AppID skip makes the focused test fail
with one unnecessary update. `#[cold]` was removed because the first
reverse and forward hits exercise this path. #12620 tracks the
zero-syscall epoch redesign; this fold does not implement it. Missing
rows or failed updates leave the verdict and session lifetime unchanged.
No live-cluster mutation was performed.
