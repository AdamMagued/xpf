# Issue #12208 — add verifier and installer negative cells

## Why

Production verification already fails closed, but there were no consumer-level regression cells for absent/empty minisign signatures, an artifact outside a signed manifest, or the installer's non-dry placeholder-key refusal. The existing selftest's unsigned-manifest case exercised `publish.py`'s pre-check rather than the verifier consumer, so an active-success change in those paths could go unnoticed.

## What

Added `scripts/dist/test_verify_negative_12208.py` with real throwaway-minisign fixtures and consumer entry points:

- `verify-file`: a valid signed positive control, plus absent and empty signature refusals.
- `verify`: a valid signed listed-artifact positive control, plus absent and empty manifest-signature refusals and an unlisted-artifact refusal.
- `install.sh`: a non-dry placeholder-key refusal with `EXIT` cleanup
  disabled so transient writes remain observable, plus assertions against
  source-write and rollback output and the full refusal phrase. `KEYRING`,
  `SRC`, and `PIN` are redirected; a stamped non-placeholder control
  reaches sandboxed writes. The test stubs root identity, `install`,
  preflight, and post-validation install behavior; it does not touch host
  keyrings/source lists or run apt.

No production files or `debian/changelog` were changed. The new file is covered by `scripts/run-selftests.sh`'s existing `scripts/dist/test_*.py` discovery loop.

## Risk / residual
