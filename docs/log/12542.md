# #12542 — flowexport family-ID suffix byte-ambiguous with template names

- **Timestamp**: 2026-10-10 (PR #12556 review fold 2026-10-12)
- **Action**: Backslash-escape each hashed field in `stableExporterID` so a literal `|` in an instance/template name cannot forge a field boundary or the `|v6` family suffix.
- **Base**: `origin/master` `11ab71b1c` (rebased from `f9cb48ed8` for the PR #12556 review fold)
- **Files**: `pkg/flowexport/exporterid.go`, `pkg/flowexport/exporter_id_pipe_12542_test.go`, `pkg/flowexport/README.md`, `docs/log/12542.md`

## Why

GLM R1 F1 on PR #12364 (parent-reproduced): `stableExporterID` hashes
`protocol|instance|template` + literal `|v6` for inet6. An inet template
literally named `t|v6` hashes byte-identically to inet6 template `t` (both
3185142171). The config parser accepts quoted pipes with no charset gate, and
the ambiguity is general (any `|` shifts field boundaries).

## What

- `appendEscapedField`: `\` → `\\`, `|` → `\|` before joining. Injective:
  literal `|` bytes become pure separators; the family suffix is unforgeable
  by name content. NOT length-prefix (would renumber every inet id, breaking
  the #12148 migration pins 3503984933/2107433690) and NOT a charset gate
  (larger compiler surface, leaves the class half-fixed).
- The escaped key is built in a `[128]byte` stack buffer and hashed with one
  `Write`; a longer key spills to the heap with the same bytes.
- Regression: one family-crossing pair per escaping rule (both protocols),
  the field-boundary pair, a same-family determinism battery, and a
  zero-allocation pin. Names without `|` or `\` hash bit-identically (inet
  pins GREEN unchanged); names containing `|` (previously ambiguous) or `\`
  (the escape character) get new ids.

## Review fold (PR #12556)

The Opus review of `f554e0153` returned NEEDS-FOLD with four findings and a
nit.

- **F1** — two of the three escaping rules had no test: dropping the `\`
  rule or writing the instance raw left every cell green while reopening a
  collision. Added `TestStableExporterIDBackslashFamilySuffixDistinct12542`
  (inet6 template `t\` vs inet template `t|v6`) and
  `TestStableExporterIDInstanceForgedFamilySuffixDistinct12542` (inet
  instance `i|t` with template `v6` vs inet6 instance `i` with template
  `t`), both protocols.
- **F2** — the contract comment ran straight into the helper's comment, so
  Go attached it to the helper and `stableExporterID` had none; its summary
  still described the unescaped format. The comments are now separate and
  the summary describes the escaped join (`go doc -u stableExporterID`
  shows it).
- **F3** — the helper's "allocation-free" claim was false: writing each byte
  through the `hash.Hash64` interface allocated per byte (19 allocs/call for
  netflow9 `inst0`/`tmplA`). The stack-buffer build above makes it 0, pinned
  by `TestStableExporterIDZeroAlloc12542`.
- **F4** — names with `\` but no `|` were never ambiguous yet change ids.
  The code comment, README, this log, and the commit Risk line now say
  names containing `|` (previously ambiguous) or `\` (the escape character)
  get new ids; the README records the #12542 migration and the new test
  file; the commit Risk line's literal `\\` is gone.
- **F5** (nit) — range-over-int loops in the helper and the battery.

## Risk

Names containing `|` (previously ambiguous) or `\` (the escape character)
get new ids, so collectors see a new SourceID/ODID for exactly those groups
— e.g. v9 inet `inst0`/`C:\flows` 1657165956 → 1367628185 and `inst0`/`a\b`
1304199020 → 3391822590. Names without either byte keep their ids. The
review fold hashes the same bytes as `f554e0153`, so it adds no migration.
HA symmetry preserved (still a pure function of the same four config-synced
inputs). No live cluster mutated.
