# Issue #12512 — union repeated interface sampling siblings

## Why

`compileInterfaces` used `FindChild("sampling")` in both the `inet` and
`inet6` family readers. With repeated hierarchical siblings, only the first
was read, so the later input or output presence flag was silently dropped.

## What

- Both family readers now iterate `FindChildren("sampling")` and OR the
  input/output presence flags into the compiled unit.
- `TestInterfaceSamplingRepeatedSiblings12512` covers input/output in both
  sibling orders for both `inet` and `inet6`.
- The compiler remains the only changed behavior surface. The editor-first
  mismatch is owned by #12508; filter bindings are outside this change.
- no schema doc change: presence-flag union matches flat set.

## Validation

- RED before the compiler fix: input-then-output siblings failed both family
  cases because `SamplingOutput` was false.
- First-sibling input mutant: the forward-order rows passed, but the reversed
  output-then-input rows failed in both families because `SamplingInput` was
  false. Restoring the union made all four rows pass.
- DeletePath P14 probe: targeted `sampling output` deletion returned
  `path not found: no node matching "output"` and matched `ErrPathNotFound`.
  Deleting the `sampling` container removed only the first sibling; the output
  sibling remained and compiled as `SamplingInput=false`, `SamplingOutput=true`.
- All tests in `parser_services_test.go` plus
  `TestInterfaceFilterScalarDuplicatesLastWins12093` passed (25 test functions).
  `gofmt -l pkg/config/compiler_interfaces.go
  pkg/config/parser_services_test.go` produced no output;
  `go vet ./pkg/config` passed.
- The full config package suite has known base failures: branch and unchanged
  base `bbbbf9dee` reproduce the inventory, API-auth expiry, routing-instance,
  slot-escape failures and the 10-minute `TestSchemaSpellingDifferentialGate`
  timeout. These are owned by #12581 (pkg/config) / #12553 (cross-package CI).

## Risk

Persisted configs with repeated sampling siblings change meaning on upgrade:
previously omitted input/output flags become true with no diagnostic. The
editor-first mismatch is owned by #12508; targeted deletion of a later sibling
loudly returns `path not found`, while deleting the container removes only its
first sibling. Pre-existing base failures are owned by #12581 (pkg/config) /
#12553 (cross-package CI). No schema or runtime wiring changed.
