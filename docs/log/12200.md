#12200 — Traffic-carrying, version-asserting rolling-upgrade gate

Depends on #12413 (merged as `3fc262cfb`); the #12198 HA-smoke changes are
inherited from master, not copied by this PR.

## Changes

- Added `make test-rolling-upgrade`, an `ha-smoke` cluster gate whose `.deb`
  prerequisite builds before the shared-cluster lock is acquired. The Makefile
  wraps both the measurement and ledger attestation in `with-cluster.sh`; the
  script's `cluster-cell.sh` lock entry is re-entrant. It runs one
  eight-stream iperf3 session at 100-ms intervals across the real
  secondary-first `cluster-setup.sh deploy all` path.
- Added optional timestamped `cut_start`/`cut_end` markers around each deb
  `xpfd upgrade --rolling` call. With `XPF_ROLLING_UPGRADE_TRACE` unset the
  deploy path is unchanged.
- Before any cluster mutation, the gate compares the staged xpfd version token
  from the candidate .deb with each live `/proc/<MainPID>/exe` token. Equal
  tokens produce `VERSION VOID-77` and require an older baseline deployment.
  It then samples both live image SHAs through the cuts and requires both nodes
  to finish on the candidate SHA plus a sampled mixed-version interval.
- Added `scripts/rolling_upgrade_oracle.py`: one interval/per-stream verdict
  per cut, a whole-run zero-window verdict, a version/mixed-version verdict,
  100-ms evidence-width/gap checks, no-op-build rejection, and fail-closed
  evidence parsing. The harness retains VERSION/CUT/RUN attribution and prints
  the metrics-parser diagnostic contents. The hermetic #10261-shaped red replay
  uses the preserved historical per-stream starvation log from
  `docs/log/10023/raw/historical/iperf.log` (the #10261 report itself has no raw
  evidence fixture).
- Required helper attestation on the new Makefile gate and updated its census
  from 23 to 24 invocations; registered the gate in the `ha-smoke` adapter and
  HA SMOKES wiring censuses, ledger coverage declaration, and ledger adapter
  documentation. The coverage row remains declared unreached until a live run
  records the first real cluster row; no synthetic measurement was added.
- The failover-client selftest changes the optional interval from 1s to
  100ms to match the rolling-upgrade client. The throughput selftest retains
  the stress-failover verdict-call and catch-all checks, and pins the rolling
  oracle's interval-width limit and client sampling interval. The unrelated
  locals reorder is omitted. The deploy-info line and
  `failover-client-lib.sh` comment continuation are restored.
