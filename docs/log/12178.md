# Issue #12178 — align padded CIDR-mask validation with the userspace helper

- **Timestamp**: 2026-10-08
- **Why**: The #12047 strict gate and publication mirror treated every leading-zero mask as helper-incompatible, but ipnet 2.12.0 accepts IPv4 masks up to two digits (for example `/08`) and IPv6 masks up to three (for example `/032` and `/064`). Strict commits therefore rejected some already-installed values, and the mirror falsely reported them as unpublishable.
- **What**: `CIDRMaskHelperRefusesPadding` identifies valid Go CIDRs whose padded mask exceeds ipnet's family-specific digit limit; the old `CIDRMaskHasRedundantLeadingZero` name was misleading for supported forms such as `/08`. Strict/tolerant policy and address-book fixtures and the publication mirror agree with the helper. The R1 follow-up normalizes supported padding before the junos-host `netip` resolver and detects mapped prefixes with padded masks before strict address-book acceptance.
- **Files**: `pkg/config/cidr_mask_ipnet.go`, `pkg/config/cidr_mask_leading_zeros_12047_test.go`, `pkg/config/compiler_earlystrict.go`, `pkg/config/compiler_validate_strict_addrbook_mask.go`, `pkg/config/compiler_validate_strict_policy.go`, `pkg/config/compiler_opts.go`, `pkg/config/junos_host_deny_resolve.go`, `pkg/config/addr_family.go`, `pkg/config/addressbook_mapped_prefix_10688_test.go`, `pkg/dataplane/userspace/policies_cidr_mask_12047_test.go`, `pkg/dataplane/userspace/policies_reject.go`, `pkg/dataplane/userspace/policies_reject_addrbook_family_10688_test.go`, `userspace-dp/src/policy_tests.rs`.
- **RED-before**: On base `a714c90d4`, strict book and inline-policy repros rejected helper-accepted `10.0.0.0/08`, `2001:db8::/032`, and `2001:db8::/064`. A pinned ipnet 2.12.0 parser probe accepted those and `2001:db8::/024`, while rejecting IPv4 `/024` and IPv6 `/0064`.
- **Validation**: `go build ./pkg/config ./pkg/dataplane/userspace`; `gofmt -l` on changed Go files (no output); `go test ./pkg/config/ -run 'TestCIDRMask' -count=1`; `go test ./pkg/dataplane/userspace/ -run 'TestPolicySnapshot.*(CIDRMask|Padding)' -count=1`; `cargo test --locked padded_policy_masks_match_helper_ipnet_grammar_12178`.

- **Broader-suite residual**: `go test ./pkg/config ./pkg/dataplane/userspace -count=1` was not green: unrelated config schema/auth/packing and userspace zone/retained-xfrmi/wire-shape tests failed, and `TestSchemaSpellingDifferentialGate` exceeded the suite's 10-minute timeout. The reported failures reproduced in targeted runs on clean base `a714c90d4`; the isolated spelling-gate test passed there with a 20-minute timeout (783s). The scoped #12178 tests above passed.
- **Risk**: The predicate mirrors ipnet 2.12.0's two-digit IPv4 and three-digit IPv6 parser limits. The Rust regression pins the affected parser behavior so a dependency grammar change is visible. No live-cluster mutation was performed.

## R1 review follow-up — 2026-10-11

- **F1**: `junosHostResolveAddrSet` now normalizes helper-supported padded masks before `netip.ParsePrefix`; malformed and helper-refused forms remain unrepresentable. The regression keeps a canonical sibling deny rendered alongside padded IPv4 and IPv6 denies.
- **F2**: `FRRAddrIsMapped` now recognizes padded, Go-valid mapped prefixes, so strict address-book validation rejects them rather than accepting a snapshot the helper refuses for its family split. The mirror still reports that whole-snapshot refusal for tolerated legacy config.
- **m1–m4**: Predicate tests pin mapped `/096` versus `/0096`, plus invalid out-of-range masks; the predicate was renamed to `CIDRMaskHelperRefusesPadding`; option and error wording now distinguish helper-refused padding from supported padded forms.
- **RED baseline**: Recreated the 6,345-string Go/Rust corpus. Before the fold, inline acceptance had 0 over-accepts and 0 under-accepts, while 110 mapped prefixes were strict-accepted but filed by Go in `prefixes_v4` and rejected by the helper as IPv6.
