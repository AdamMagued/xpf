# #12168 — rebind cluster comms when management VRF membership converges

- **Issue**: #12168 — a failed management-VRF bind can strand cluster comms after a later successful rebind.
- **Branch**: `fix/12168-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12168`
- **Base**: `83b5c955335f16d8c7835f206b210ce3ae1a5fe5`

## Why

The published management-VRF set describes desired membership, not kernel state. A socket may bind during retry after networkd briefly stripped its interface, while the epoch key still records the device selected at startup. A key-only comparison then misses the off-key socket after reassert or step 2.7. In addition, bootstrap reassert must not consume the #7901 restart debt with a nil config, and an unavailable/outside fab1 must not veto the healthy primary-fabric binding.

## What

- Use one transport binding predicate for key comparison and socket setup: every selected primary interface must be both a published management-VRF member and a kernel slave of `vrf-mgmt`. This preserves working main-table comms after EBUSY and catches warm-restart publication after kernel membership persisted.
- Keep the epoch-start device as the expected key, but resolve each bind attempt afresh. A mismatch sets a sticky epoch bit through `setActiveTransportIfCurrent`; later applies or reasserts then restart every socket together, even if the latest lookup again matches.
- Use only the primary sync transport interface for the session-sync/fabric-gRPC VRF predicate and key. Secondary addresses may still open secondary sockets, but a missing or outside-VRF fab1 cannot veto the healthy primary.
- Keep #7901 debt consumption in step 20. The reassert caller does not take debt and exits its transport reconcile for nil config, no cluster stanza, or bootstrap mode.
- Add X1/X2 strip-retry regressions, D1 rollback-debt tests, F1a/F1b dual-fabric kernel tests, and non-namespace M5/M7/M8/M9 wiring tests. Fail closed on child EPERM except when the dedicated namespace-capability probe cannot run.
- Re-resolve heartbeat restart, session-sync retry, fabric-gRPC listener retry, CLI and gRPC peer-dial bindings from the same predicate.
- Add the VRF device to the heartbeat-started log and warn when a published interface is stripped from the management VRF.
- Keep P1/P2 warm-boot, P3/P3b reassert-only and P4 converging-commit regressions, plus a `NewServer` peer-dial resolver regression. Preserve the existing cluster socket test that verifies `SO_BINDTODEVICE=lo`.
- Shorten Unix-socket fixture basenames in long daemon tests so their paths remain within Linux `sun_path` under the lane-local scratch root.
- NOT changed: a VRF churn hold-down; retry timing remains unchanged.
