# #12168 — rebind cluster comms when management VRF membership converges

- **Issue**: #12168 — a failed management-VRF bind can strand cluster comms after a later successful rebind.
- **Branch**: `fix/12168-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12168`
- **Base**: `83b5c955335f16d8c7835f206b210ce3ae1a5fe5`

## Why

The published management-VRF set describes desired membership, not kernel state. After an EBUSY bind, using that set for step 20 can restart working main-table comms and publish a VRF key before any socket has converged; the later real bind then repeats the same key and cannot recover the heartbeat or session-sync listener. The daemon-owned gRPC server and CLI also retained the peer-dial VRF captured at startup, so diagnostics remained on the old route after listeners rebound.

## What

- Use one transport binding predicate for key comparison and socket setup: every selected interface must be both a published management-VRF member and a kernel slave of `vrf-mgmt`. This preserves working main-table comms after EBUSY and catches warm-restart publication after kernel membership persisted.
- Re-resolve heartbeat restart, session-sync retry, fabric-gRPC listener retry, CLI and gRPC peer-dial bindings from that same predicate.
- Extract step 20's compare-and-restart helper and call it after successful reassert-loop rebinds, so convergence outside a commit also recovers comms.
- Add P1/P2 warm-boot, P3/P3b reassert-only and P4 converging-commit regressions, plus a `NewServer` peer-dial resolver regression. Preserve the existing cluster socket test that verifies `SO_BINDTODEVICE=lo`.
- Shorten Unix-socket fixture basenames in long daemon tests so their paths remain within Linux `sun_path` under the lane-local scratch root.
- NOT changed: a VRF churn hold-down, because this fold is limited to B1/B2/B3 and coverage/evidence; retry timing remains unchanged.
