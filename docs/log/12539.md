# #12539 — mgmt-VRF ECMP static with realm stamp fails RouteReplace

- **Timestamp**: 2026-10-10
- **Action**: Stamp the xpf ownership realm only on single-path mgmt statics; ECMP (multipath) routes carry realm 0.
- **Base**: `origin/master` `f9cb48ed8`
- **Files**: `pkg/daemon/mgmtvrf_static_routes.go`, `pkg/daemon/mgmtvrf_static_ecmp_realm_12539_test.go`, `docs/log/12539.md`
- **Parent**: #12084 (GLM second-model residual on PR #12332, reproduced firsthand)

## Why

Kernel 7.2.8 rejects RTA_FLOW on multipath routes. `mgmtStaticRoutesDesired`
stamped Realm 0x585046 on EVERY desired route and set MultiPath on 2+-leg
tiers — so any ECMP mgmt static failed RouteReplace with EINVAL and never
installed. Single-path + realm installs fine; multipath without realm
installs fine; only the combination fails.

## What

Moved the realm assignment into the `len(hops) == 1` branch (single-path
byte-identical, incl. the backup-router route). ECMP keeps legs/Gw-nil/
LinkIndex-0 with realm 0. Key/fake/backup untouched: `mgmtStaticRouteKey`
is realm-free, so steady ECMP matches kernel state (no churn); the
applied-set protects fresh installs; cleanup skips realm-0.

Known gap (documented, out of scope): an ECMP static fully removed from
config leaves a stale realm-0 ECMP route unreaped (indistinguishable from
operator ECMP in table 999 — reaping it would risk operator routes).
Leg-changes self-heal via dst-keyed replace.

## Validation

- RED: stashed fix → ECMP realm assertion FAILS (0x585046).
- GREEN: new test PASS (ECMP realm-0 + legs .1/.3, single realm + gw/7);
  11792/11449/12084 neighbor suites GREEN; gofmt/vet clean.

## Risk

Minimal: single-path behavior byte-identical. The full-removal leak above
is the accepted tradeoff (documented). No live cluster mutated.
