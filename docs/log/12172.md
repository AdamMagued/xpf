# #12172 — announce IPv6 proxy-NDP pool addresses after RG failover

- **Issue**: #12172 — IPv6 proxy-NDP pool neighbor entries stay bound to the former RG owner's per-node RETH MAC until upstream NUD expires.
- **Branch**: `fix/12172-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12172`
- **Base**: `83b5c955335f16d8c7835f206b210ce3ae1a5fe5`

## Why

The RG failover pool announcement refreshed IPv4 addresses with a gratuitous
ARP but skipped IPv6 addresses. Sending IPv6 through the ARP path would be
invalid, and no pool-target unsolicited NA replaced it. Because RETH MACs are
per-node, an upstream neighbor entry could continue forwarding IPv6 return
traffic to the former owner until NUD aged it out. Kernel proxy-NDP can answer
solicited Neighbor Solicitations when `proxy_ndp` and FIB conditions match.
Forwarded unicast NUD probes with `all.proxy_ndp` unset are a separate recovery
gap tracked in #12611.

## What

- Send one gated unsolicited NA for each IPv6 proxy-NDP pool address from the existing failover announcement path; keep IPv4 pool addresses on their GARP path.
- Build proxy-target NAs with an explicitly assigned interface source distinct
  from the target. Proxy-target announcements use Router=0, matching the
  kernel's NTF_PROXY-only replies; VIP and router link-local announcements
  retain Router=1 under RFC 4861 §7.2.5.
- The raw sender prefers an assigned global/ULA source when available and
  falls back to link-local; Linux route-based source selection for ff02::1 may
  instead choose link-local.
- Keep the existing RG ownership predicate and `stillValid` fence for both families. Share the 64-address per-failover budget across IPv4 and IPv6, counting attempted sends so failures cannot reopen the socket fan-out budget; retain configured-order truncation.
- Clarify that reconcile-time v6 entries skip unsolicited NA because they need none to start answering; stale-binding invalidation is handled by the RG failover path.
- Add a deterministic upstream neighbor-cache aging fixture with a v4 GARP control, v6 NA assertion, ownership-fence checks, mixed-family budget checks, and send-failure budget coverage.
- Capture the NA sender in the 8405 IPv6 control and assert its target,
  keeping that unit test away from raw-socket I/O.
