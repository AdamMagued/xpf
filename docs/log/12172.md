# #12172 — announce IPv6 proxy-NDP pool addresses after RG failover

- **Issue**: #12172 — IPv6 proxy-NDP pool neighbor entries stay bound to the former RG owner's per-node RETH MAC until upstream NUD expires.
- **Branch**: `fix/12172-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12172`
- **Base**: `83b5c955335f16d8c7835f206b210ce3ae1a5fe5`

## Why

The RG failover pool announcement refreshed IPv4 addresses with a gratuitous ARP but skipped IPv6 addresses. Sending IPv6 through the ARP path would be invalid, but no pool-target unsolicited NA replaced it. Because RETH MACs are per-node, an upstream neighbor entry could continue forwarding IPv6 return traffic to the former owner until NUD aged it out. Solicited NDP responses eventually recover; they do not immediately invalidate a cached binding during failover.

## What

- Send one gated unsolicited NA for each IPv6 proxy-NDP pool address from the existing failover announcement path; keep IPv4 pool addresses on their GARP path.
- Keep the existing RG ownership predicate and `stillValid` fence for both families. Share the 64-address per-failover budget across IPv4 and IPv6, counting attempted sends so failures cannot reopen the socket fan-out budget; retain configured-order truncation.
- Clarify that reconcile-time v6 entries skip unsolicited NA because they need none to start answering; stale-binding invalidation is handled by the RG failover path.
- Add a deterministic upstream neighbor-cache aging fixture with a v4 GARP control, v6 NA assertion, ownership-fence checks, mixed-family budget checks, and send-failure budget coverage.
- Update the 8405 IPv6 control to capture the NA sender and assert the
  target, keeping that test hermetic.
