# #12229 — deny lifeline-shared addresses on data ingress

- **Timestamp**: 2026-10-08 (`fix/12229-campaign-pub`)
- **Action**: preserve lifeline-shared addresses outside destination-only deny-all policy while judging them against each ingress zone's own policy, including unzoned and ambiguous ingress.

## Red before

On base `a714c90d472a3c3d98a3799831cfef3ec311a61c`, the regression's generated-rules check failed because no ingress-only drop for `192.0.2.1` was emitted. The isolated kernel scenario also confirmed the defect: an SSH connection to the shared address through the untrust veth was connected instead of timing out, for both the text oracle and production netlink installer.

## Change

- The host-inbound view carries separate IPv4/IPv6 lifeline-shared values that remain withheld from destination-only service policy in empty-admit views.
- Both judged-destination helpers include those withheld values, so every zone ingress scope applies that zone's service policy to the shared address; fxp0 remains outside data ingress scopes.
- Text and production netlink renderers apply the drop before the residual established accept. The cold-boot fence still withholds the shared value, and the config duplicate-checker's lifeline skip is unchanged.
- Updated `docs/host-inbound-service-matrix.md` to document cross-zone policy, management preservation, and cold-boot behavior.
