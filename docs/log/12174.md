# Issue #12174 — re-stop and re-snapshot a STOPPED resume

## Why

A durable `STOPPED` journal does not prove systemd stayed down. FLIP changes
`versions/current` at 6a before the systemd drop-in is reloaded at 6c. A crash
in that window can leave the old executable loaded, and a reboot or operator
restart can run it and accept commits after the original rollback snapshot.
Even a successful daemon-reload leaves an already-running old process intact.
Reusing the stale snapshot during rollback loses those commits. Conversely, a
target process may already have migrated the DB, so its snapshot must survive.

## What

On `STOPPED` resume, the runner compares `versions/current` with systemd's
loaded `ExecStart` and the executable of `MainPID` (`/proc/<pid>/exe`). The
on-disk drop-in is insufficient: it is written before 6c, and daemon-reload
does not restart a running process. If current names the previous version, or
current names the target while either loaded or running execution remains
previous, the runner stops again, captures a fresh cut-boundary snapshot, and
durably saves its path before FLIP. If current and execution identify target,
the original rollback snapshot is preserved because the target may already
have migrated the DB. A target ExecStart with a previous MainPID remains an
old-process case: on snapshot/persistence failure, restore the previous
drop-in and reload before restarting it. Unknown paths
and contradictory combinations (including target current/MainPID with previous
loaded ExecStart) refuse with recovery guidance and retain journal/snapshot.
`UnitAlreadyStopped` remains caller-owned and is not restarted.

Added regression cells for the 6a-only restart/commit window, 6c written
before reload, a previous process surviving successful daemon-reload, healthy
target and full-flip controls, fail-closed refusal guidance, caller-owned
stopped units, and snapshot and journal-persistence recovery. The prior
same-path duplicate test and obsolete STOPPED-down invariant were removed.
Docs now describe current, loaded ExecStart, and running MainPID as separate
signals.

## Risk / residual

Systemd loaded state and `/proc/<MainPID>/exe` are covered through command
fakes, not a live reboot or systemd restart. Unknown or contradictory
runtime/version state intentionally refuses and requires operator recovery.
