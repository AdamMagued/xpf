# Issue #12123 — structured merge diagnostics for spaced instance names

- **Issue**: #12123 — unnamed routing-container folds under quoted spaced routing-instance names received the named-instance warning.
- **Branch**: `fix/12123-merge-diag`
- **Worktree**: `/var/worktrees/12123-merge-diag`
- **Base**: `fe225f7f45ca892dbfe90e5b369ff1a5d2438b9f` (#12120 stacked first)

## Why

`mergeDuplicateBlocks9023` flattened merge context into a space-joined string. An unnamed fold under the quoted instance name `"a b"` therefore lost token boundaries, and the `strings.Count(what, " ") == 2` classifier rejected it as an unnamed fold. The diagnostic fell through to a false duplicate routing-instance definition warning. The spaced VRF name remains independently quarantined by #11391; this change affects diagnostics only.

## What

- Preserve merge kind, parent, keyword, and instance/name in a structured descriptor from the fold through warning formatting; do not infer unnamed/named status from flattened text.
- Quote spaced instance names in the unnamed-merge warning scope while leaving simple names and existing warning text unchanged.
- Add an end-to-end quoted-name regression for unnamed `routing-options` and `protocols` folds, plus a named routing-instance control whose name ends in `routing-options`.
- Update #12120's direct warning fixture to match structured merge context.
