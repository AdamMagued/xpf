# Issue #12204 — pin expired first-commit recovery markers

## Why

The branch-executing `TestActiveSnapshotRecoveryFirstCommitNil9905` asserts only the nil snapshot; it does not directly pin `EverCommitted` or the committed disk marker on the plain no-rescue expiry path. This is a direct-assertion gap, not a claim that the full suite misses all mutants: #11802 catches M1/M3 indirectly on the rescue path through `Load`'s return, and #12167 pins the retry seed during sentinel-failure healing.

## What

Added an end-to-end configstore oracle for a genuine first `CommitConfirmed` whose deadline expires while the daemon is down. It directly asserts the immediate `ActiveConfig()==nil` and `EverCommitted()==false` state, the disk `committed=false` marker before and after reopen, and the marker after a failed recovery write followed by a successful retry. Added a daemon-package consumer check that feeds the recovered store predicates to `computeBootClass` along with fixed `false, false` non-fail-closed inputs; it does not exercise `daemon_run_bringup.go` (CS1 survives by design).

## Validation

- **STEP-0** (`a714c90d472a3c3d98a3799831cfef3ec311a61c`): `TestActiveSnapshotRecoveryFirstCommitNil9905` asserted only the nil active snapshot and passed with each of the three individual marker mutants in that targeted test.
- **Direct-assertion gap:** `TestRescueFallbackExpiredConfirmRecoveryKeepsBootstrapProvenance11802` catches M1/M3 indirectly through `Load`'s return on the rescue path; `loadRescueFallbackLocked` re-clears both flags and cannot directly pin this no-rescue path's marker seed. `TestFirstCommitRollbackSentinelWriteFailureFailsClosed12167` from #12167 pins that seed through sentinel-failure healing.
- **GREEN after:** the new oracle fails each mutant at its direct no-rescue assertion: M1 fails `EverCommitted`, M2 fails the healed disk marker, and M3 fails the reopened disk marker. All three mutated production edits were restored.
- `go test ./pkg/configstore/ -run 'TestFirstCommitRecoveryOracle12204|TestActiveSnapshotRecoveryFirstCommitNil9905|TestConfirmRollbackKeepsNeverCommittedAfterItem1bRestart' -count=1` and `go test ./pkg/daemon/ -run TestExpiredFirstCommitRecoveryBootClass12204 -count=1` passed.

## Risk / residual

Test-only change; no production code or live cluster/hardware was changed. The daemon consumer check edits only a temporary plaintext first-commit `confirm.json` deadline to deterministically model downtime.
