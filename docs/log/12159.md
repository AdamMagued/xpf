# Issue #12159 — demote a crash-looping userspace helper

## Why

The shim deliberately stays attached and drops transit when its helper dies, but the daemon treated `armed && attachedXDPLinks > 0` as readiness. That left the host transit gate open and the incumbent RG at weight 255 while traffic was blackholed. A helper restart in progress must close transit immediately; a persistent crash loop must also resign the incumbent so it cannot hold a blackholed RG.

## What

- The userspace manager and legacy adapter expose a synchronized helper-supervisor snapshot and a wake-only observer. The daemon registers the observer with the published dataplane and re-reads state on each wake/tick.
- Transit opens only with kernel/XDP readiness and a running helper. One fast restart closes the gate but does not flap the incumbent. Once restart backoff reaches its cap, a dedicated reserved monitor applies full election debt (weight 0) so even a non-preempt incumbent yields. A landed supervisor retry clears live HA debt while preserving the episode record until the quiet-window or Compile boundary; kernel-arm debt remains independent.
- All production gate-opening paths, including rxvlan audit reassertion, use the helper predicate. The helper-loop monitor is preserved across unrelated monitor reconciliation. The dataplane docs describe the fail-closed and election behavior.
- Regression fixtures cover both preempt settings, a fast restart, persistent crash-loop demotion, and recovery; supervisor tests cover running, single-crash, failed readiness at the cap, and observer delivery.

## Review fold (#12374, NM-1–NM-4)

- **NM-1 — failed bring-up counts as a retry.** A failed supervisor retry now
  increments the counted attempt and notifies the observer; Compile-path
  rearming still preserves the count because that path did not prove recovery.
  The 5838 regressions pin the 6-to-7 transition, fail-closed state, and use of
  the current desired config after a failed retry.
- **NM-2 — quiet-window reset and episode journal.** A quiet interval longer
  than twice the maximum backoff starts the next unexpected exit at attempt 1,
  rather than accumulating isolated crashes into a false loop. On the existing
  periodic status-loop tick, a still-running recovered helper's completed
  episode is journaled and cleared after that same quiet window; if an
  unexpected exit observes expiry first, it performs the closure there. The
  journal retains the actual readiness time. No separate expiry timer is
  needed, and a healthy recovery is recorded without requiring another crash.
- **NM-3 — recovered means running.** A landed retry remains visible as
  recovered-running while its episode debt is open; the forwarding-status
  renderer no longer calls that live helper stopped. Intentional stop clears
  the live-recovery marker, while ordinary generation-advancing Compile still
  closes the episode.
- **NM-4 — portable cadence and production-path coverage.** Crash-cadence
  fixtures use `t.TempDir`; real-child episode and Compile regressions exercise
  restart/reset behavior, with daemon election-debt and fwdstatus rendering
  regressions covering their production consumers.
- The earlier fold remains: RG0 is excluded from crash-loop resignation so a
  lone-node config store remains writable; daemon election debt preserves
  unrelated arm debt; recovery-weight assertions poll to avoid the prior
  immediate-read race between separate knob and election-debt passes.
- **Crash-accounting follow-up.** Failed supervisor retries refresh the
  quiet-window anchor, so repeated failed attempts cannot make a later brief
  landing appear stable. The Prometheus counter increments on unexpected
  exits of helpers that reached readiness, independently of the completed-
  episode ring; failed pre-readiness starts are excluded while `Restarts`
  continues to track them. NM-2 tests capture and fire supervisor retries
  directly rather than racing a 1 ms real timer.
- **Fold RED/GREEN evidence.** NM-1: removing retry rearming leaves the
  failed-restart fixture at 6 rather than 7 attempts and without the loop
