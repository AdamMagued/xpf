# 12217 — Quarantine unknown `security policies` children

## Why

A misspelled child such as `security policies globel` was rejected by strict schema validation but silently dropped when a persisted configuration was loaded tolerantly. The Store retained a permit fallback without the authored deny rulebase, and neither warnings nor policy-snapshot poison recorded the loss.

## What

- Record every unknown direct child under `security policies` during compilation.
- Keep strict compilation rejection; tolerant Load/SyncApply records a diagnostic and adds a synthetic `LenientContentDropped` carrier so the userspace policy snapshot is refused instead of installing an incomplete rulebase.
- Carry recorded child names on the synthetic carrier so userspace rejection diagnostics identify the skipped `security policies` child.
- Add config and SyncApply regressions for multiple unknown children, strict rejection, lenient warnings, carrier creation, and the apply-macro control.
- Add a Store.Load regression using `globel`, a permit-all fallback, a deny rule, and a strict-schema control.
