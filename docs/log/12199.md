# Issue #12199: Verify RG1 movement in stress failover

- **Timestamp**: 2026-10-07
- **Action**: Added a shared fail-closed stress oracle. Each RG1 failover/failback half-cycle now polls `show chassis cluster status` on both nodes until each view shows the requested node as primary for RG1 and the other node as secondary or secondary-hold, or the 30-second attempt budget expires; an unchanged/unreadable owner fails the cycle. The non-owner may remain secondary-hold after an untargeted manual failover until reset. Request return codes and stderr are retained for diagnosis, with observed ownership—not the request text—as the verdict. A final two-node read requires RG1 back on fw0. `check_streams` now fails when the tail has fewer than `IPERF_STREAMS` rows.
- **Regression**: Added `stress-failover-selftest.sh` with hermetic checks for empty/short stream tails, dead-stream rows, RG1 scoping, unchanged ownership, blind/duplicate rows, bounded polling, real-output secondary-hold, split-view rejection, successful movement and final-owner validation, request-error reporting, and whole-harness mover/stuck controls. Registered it with the hermetic runner and declared the sourced library in the harness census.
